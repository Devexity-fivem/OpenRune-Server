## Gotchas hit (worth knowing before your first run)

1. **Stale CS2 tree.** `freshCache` unpacks a versioned CS2 bundle into
   `%LOCALAPPDATA%\OpenRune\cs2` (Linux: `~/.local/share/<name>/cs2`). This machine
   already had a bundle from an older revision; scripts decompiled against it
   reference enum ids that no longer exist → `enum_3341 could not be resolved`.
   Fix: `./gradlew :or-cache:cleanCs2` then re-run `install`. If you ever see
   symbol-resolution errors in `.cs2` files during `freshCache`, this is why.

2. **Orphaned JavaExec process.** When `freshCache` crashed mid-`RemoveBzip`,
   the forked JVM stayed alive and kept `.data/cache` files locked
   (`rm: Device or resource busy`). Check `Get-Process java` / kill the
   `dev.openrune.CacheToolsKt` process before wiping `.data/cache`.

3. **`install` reports FAILURE even on success.** The `install` JavaExec task
   isn't configuration-cache compatible (`cannot serialize Gradle script object
   references`). The work itself finishes — look for
   `Installation process completed.` and check that `game.yml`,
   `.data/client.key`, and `.data/game.key` exist. Pre-existing repo issue, not
   something to fix locally. `./gradlew install --no-configuration-cache` exits
   cleanly.

4. **README strings drifted.** A successful boot now prints
   `Server ready in Ns` (what CI greps for), not
   `OpenRune Server Successfully initialized`. `Loaded up in x ms` means the
   cache/install step was skipped.

5. **Revision is 241** (`game.example.yml`), not 240.2 as `AGENTS.md` says.

## Connecting a client (you, on Windows)

RSProx is the only supported client path. RSProx-for-private-servers works on
Windows and Linux, not macOS.

1. Download the latest RSProx release:
   https://github.com/blurite/rsprox/releases
2. `⊞ + R` → `%USERPROFILE%` → open/create `.rsprox` (launching RSProx once
   creates it).
3. Create `.rsprox/proxy-targets.yaml`:

   ```yaml
   config:
     - id: 1
       name: OpenRune Server
       jav_config_url: https://client.blurite.io/jav_local_241.ws
       varp_count: 15000
       revision: 241
       modulus: <paste Modulus line from .data/client.key>
   ```

   The modulus is in `.data/client.key` (generated by `install`, gitignored —
   it is per-install, don't commit it).
4. Start the server: `./gradlew run`, wait for `Server ready in`.
5. Launch RSProx, pick the `OpenRune Server` target — it launches the OSRS
   client proxied at `127.0.0.1:43594`.
6. Log in. `game.yml` defaults have `requireRegistration=false` and
   `autoAssignDisplayNames=true`, so any username/password works.

## Running locally from the fork

For testing my branches on your own machine.

### Prereqs

- JDK 21 on PATH (`java -version`). JDK 17 is picked up automatically for
  `:tools:osrs-mcp` if present — not required for the server itself.
- RSProx (below).

### First-time setup (once)

```bash
git clone https://github.com/Devexity-fivem/OpenRune-Server
cd OpenRune-Server
./gradlew install
./gradlew run
```

- `install` downloads ~250 MB of game cache from OpenRS2 plus a ~4 MB CS2
  bundle, then repacks it. Expect 2–5 min depending on connection.
- On success you will still see `BUILD FAILED` at the end — that is the
  **cosmetic configuration-cache warning** described above. What matters:
  `Installation process completed.` appears and `game.yml`,
  `.data/client.key`, `.data/game.key` exist. A real failure shows a Kotlin
  exception or `Execution failed for task ':or-cache:freshCache'` with no
  "Installation process completed" line.
- `./gradlew run` boots the server; success = `Server ready in Ns` and the
  process stays running. `Loaded up in x ms` alone means a step was skipped —
  run `install` first.
- After the first install, iteration is just `./gradlew run` — no cache work
  needed unless a `-pack` module's resources or `gamevals.toml` changed (then
  `./gradlew :or-cache:buildCache` first).

### Testing a branch

```bash
git fetch origin
git checkout <branch>
./gradlew run
```

`game.yml` is gitignored, so your config survives branch switches. Same for
`.data/` — the cache and your generated RSA keys are never committed.

### RSProx (your machine)

Same as the main checklist above — the modulus in `proxy-targets.yaml` must be
copied from **your** local `.data/client.key` (generated by your `install`
run; each install generates a fresh keypair, so a stale modulus from my
machine will not work).

### If the cache seems broken

`./gradlew :or-cache:cleanCs2` then re-run `./gradlew install`. If that still
fails, delete `.data/cache` and re-run `install` (full re-download). If files
are "busy", a previous `install` JVM is still running — kill stray
`CacheToolsKt`/`java` processes first.
