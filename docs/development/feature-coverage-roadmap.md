# Feature coverage roadmap (evidence-based parity matrix)

This file is the authoritative engineering backlog for actual feature
completion. `PROGRESS.md` (generated by `tools/progress/content-progress.mjs`)
only tracks structural presence — a module or symbol existing — and says
nothing about whether gameplay works. Statuses here are earned by evidence,
not by code existing.

Status definitions: **Not started** / **Partial** / **Implemented,
unverified** / **Verified with known gaps** / **Complete for target revision**
/ **Blocked**.

Target revision: **241** (game.yml; AGENTS.md still says 240.2 — stale).

## Agility

### Gnome Stronghold Agility Course

- Wiki: https://oldschool.runescape.wiki/w/Gnome_Stronghold_Agility_Course
- Path: `content/skills/agility/.../GnomeAgilityCourse.kt` +
  `MarkOfGrace.kt`, pack `content/skills/agility/pack` (`AgilityPluginPack`,
  `agility_vars.toml`, `gamevals.toml`), tests `GnomeAgilityCourseTest.kt`
  (cache-backed symbols) + `GnomeAgilityCourseGameTest.kt` (9 integration
  tests via GameTestExtension).
- Requirements: 7 obstacles lvl 1; log 10, net 10, branch 6.5, rope 10,
  branch 6.5, net 10, pipe 7.5 + 50 lap bonus = 110.5 XP/lap; Marks of Grace.
- Status: **Verified with known gaps** (live-verified via MCP: 1 isolated
  pipe +1125 no bonus, 2 full in-order laps +16575 each = single bonus/lap;
  trainer Talk-to fires verbatim wiki dialogue; mark not observed in 2 live
  laps — probabilistic, covered by deterministic tests).
- Implemented this batch:
  - In-order lap progress tracked in temp varp `agility_course_progress`
    (63739); bonus only when progress reaches pipe, out-of-order resets.
  - `MarkOfGrace` service: per-lap roll 2/6 (gnome exact rate unpublished —
    approximation documented), 3-min game-time cooldown in permanent varp
    `agility_mark_last_minute` (63740, persists through logout), 20+ levels
    over req → denominator x5, private `obj.grace` spawn at (2484,3418,2),
    10-min despawn/reveal.
  - Gnome trainer (`npc.gnometrainer` 6080): nearest trainer within 15 tiles
    barks wiki-verbatim lines on each obstacle; Talk-to opens the wiki's
    training-area dialogue.
- Known gaps:
  - Cycle timings eyeballed, not tick-exact vs OSRS.
  - `seq.myq3_human_tightrope` (4772) may not be the exact rev-241 gnome
    tightrope seq; looks correct live.
  - Pipe step-through walls and transmog-to-crawl-NPC cosmetics: pipe works
    via two-hop exactMove; no mid-pipe NPC transmog (visual only in OSRS).
  - Live "Total Laps" HUD increments per pipe completion (existing engine
    behavior, not course code).
- Next action: same lap-progress + MarkOfGrace pattern for remaining courses;
  mark spawn could not be observed live (2/6 roll failed twice).

### Kalphite Queen

- Path: `content/bosses/kalphite-queen/`. Design informed by
  `Kronos-184-Fixed/.../bosses/KalphiteQueen.java` (two forms, per-form
  protection, worker aggro); ids re-derived for rev-241 (`npc.kalphite_queen`
  963, `npc.kalphite_flyingqueen` 965, `npc.kalphite_worker` 955, verified
  seq/spotanim symbols).
- Mechanics: two 255-hp forms; grounded clamps lethal hits at 1 hp via the
  new `NpcHitpointsFloorHook` binding, then `HpExact(1)` trigger runs
  emerge (glow anim + spotanim, heal to 255, `transitionTo` flying phase,
  phase-level `transmog` to `npc.kalphite_flyingqueen`). Incoming-rule
  `ScalePercent(10)` stands in for form protection prayers. Workers roused
  on a 6t / 1-in-3 `every` timer via `kq.aggro_workers` extension
  (`npcRepo.findAll` zone scan + `apPlayer1`).
- Status: **Verified live** (2026-10-26): grounded → flying transmog with
  fresh 255 bar observed in-game, magic-chip damage on grounded form, real
  death + drops on flying form, zero exceptions.
- Gaps in docs/quirks.md: prayer model is %-scale not immunity, lightning
  doesn't chain, spines don't AoE, worker cadence is timer-based.

### Corporeal Beast

- Path: `content/bosses/corporeal-beast/`. Design informed by
  `Kronos-184-Fixed/.../bosses/corp/CorporealBeast.java` + `DarkCore.java`
  (halved non-spear damage, 100 cap, dark energy core loop); ids re-derived
  for rev-241 (`npc.corp_beast` 319, `npc.dark_core` 320,
  `spotanim.corp_spirit_beast_*_proj` 314-316, `spotanim.dark_core_jump` 319).
- Mechanics: melee stomp + weak/powered/split magic projectiles (split uses
  `debris` ground AoE); `onModifyHit` halves damage from non-Spear/Polearm
  weapon categories with the "resists your weapon" message; incoming rule
  caps hits at 100; below half hp (wiki gate) a `HitDamageAtLeast(32)`
  reaction and an `every(attackRate)` timer each roll 1/8 to summon the
  core. The core is a `NpcMode.None` summon (not a
  spec'd combat npc): a `corp.core_tick` extension every 2t drains 5-13
  typeless from each player in its 3x3 and feeds half to Corp; when nobody
  is adjacent it hops onto a player (northernmost, then easternmost) on a
  4-tick cooldown via `bossProjectile` + `telejump`.
- Status: **Verified live** (2026-10-26): resist message + halved damage,
  one core at a time (`noCoreAlive` guard on both spawn paths), core hops
  to the player, drain messages + typeless hits + Corp heal, core killable,
  zero exceptions.
- Gaps in docs/quirks.md: core isn't hidden during the hop and stays
  attackable mid-jump; poisoned-core slowdown unmodelled; Corp's off-target
  retarget (hit ≥15, 1/5) unmodelled; powered projectile doesn't vary
  through Protect from Magic.
